# .gitignore - Hướng Dẫn Các File Bị Ignore

Hướng dẫn chi tiết về các file & folder được ignore và tại sao.

## 🔒 Critical Security Files

### Environment Variables (NEVER COMMIT)

```
.env                    # Local development secrets
.env.local              # User-specific local vars
.env.*.local            # Any environment-specific vars
.env.production.local   # Production secrets
.env.test.local         # Test environment secrets
.dev.vars              # Wrangler development variables
```

**Contains:** API keys, tokens, database passwords, JWT secrets

**Example contents:**
```env
JWT_SECRET=your-secret-key-here
TELEGRAM_BOT_TOKEN=123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
TELEGRAM_SECRET=your-telegram-secret
GEMINI_API_KEY=your-google-gemini-key
```

**If accidentally committed:**
```bash
# Remove from git history
git rm --cached .env
git commit -m "Remove .env file"

# Or use BFG Repo Cleaner for large repos
bfg --delete-files .env
```

## 📦 Dependencies

### node_modules/

- **Size:** 800MB - 1GB per project
- **Reason:** Regenerated from package.json/package-lock.json
- **Recovery:** `npm install`

### Lock Files (Optional)

```
package-lock.json       # npm lock file
yarn.lock              # Yarn lock file
pnpm-lock.yaml         # pnpm lock file
```

**Best Practice:**
- ❌ Ignore lock files if you want flexibility
- ✅ Commit lock files if you want consistency (recommended for teams)

**Current:** Ignored to keep repo small

## ✅ Best Practices

### Do's ✅

- ✅ Commit `.gitignore` files
- ✅ Commit `.vscode/extensions.json` (team recommendations)
- ✅ Commit `package.json` (dependencies list)
- ✅ Create `.env.example` with dummy values
- ✅ Document required `.env` variables
- ✅ Use different `.env` files per environment
- ✅ Rotate secrets in `.env` periodically

### Don'ts ❌

- ❌ Commit `.env` files
- ❌ Commit actual API keys or tokens
- ❌ Commit node_modules/ (too large)
- ❌ Commit local database files
- ❌ Commit IDE settings unless shared
- ❌ Commit build output (regenerable)
- ❌ Share `.env` files via email/chat

## 📚 .env.example Pattern

Create a template file for team members:

**backend/.env.example:**
```env
# JWT Secret (generate: openssl rand -base64 32)
JWT_SECRET=<generate-your-own-32-char-secret>

# Telegram Bot (from @BotFather)
TELEGRAM_BOT_TOKEN=<get-from-botfather>

# Telegram Webhook Secret (generate: openssl rand -base64 32)
TELEGRAM_SECRET=<generate-your-own-secret>

# Google Gemini API (from Google Cloud)
GEMINI_API_KEY=<get-from-google-cloud>

# API Configuration
API_VERSION=1.0.0
LOG_LEVEL=debug
```

**frontend/.env.example:**
```env
# Backend API URL
VITE_API_URL=http://localhost:8788
```

**Team members then:**
```bash
cp backend/.env.example backend/.env.local
# Edit .env.local with their values
```

## 🔄 If You Accidentally Commit Secrets

### Immediate Steps

1. **Regenerate secrets immediately**
   ```bash
   # Change all credentials
   # Rotate Telegram token, API keys, JWT secret
   ```

2. **Remove from git history**
   ```bash
   # Option A: Using git filter-branch (keeps history)
   git filter-branch --tree-filter 'rm -f .env' HEAD

   # Option B: Using BFG Repo Cleaner (faster)
   # https://rtyley.github.io/bfg-repo-cleaner/
   bfg --delete-files .env
   git reflog expire --expire=now --all
   git gc --prune=now
   ```

3. **Force push to remote**
   ```bash
   git push origin master --force-with-lease
   ```

4. **Notify team members** to pull new history

## 🔍 Verify Nothing Sensitive Is Committed

```bash
# Check git history for secrets
git log -p -- '*.env' | head -20

# Search for common patterns
git grep -i "secret\|password\|token\|key" HEAD

# List all tracked files (should not include .env)
git ls-files | grep -E "(\.env|\.dev\.vars|secrets)"

# Check large files (often contain data)
git ls-files -l | sort -k5 -rn | head -10
```

## 🚨 Security Reminders

⚠️ **NEVER:**
- Commit `.env` or `.dev.vars`
- Put secrets in comments
- Log API keys or tokens
- Share `.env` via email/chat
- Include credentials in code

✅ **ALWAYS:**
- Use `.gitignore` for secrets
- Regenerate leaked credentials
- Use environment variables
- Document needed vars in `.env.example`
- Rotate secrets periodically
